# PLLangStudio：PL/SQL Developer 語言編輯與比對器

> 一句話說明：**PLLangStudio 是幫 PL/SQL Developer「換說法」的工具。**
> 它可以打開 PL/SQL Developer 的語言檔，把兩種語言並排比對，讓你修改介面上的中文翻譯，改完再放回去。

## 1. 這個工具在做什麼？

PL/SQL Developer 是寫 Oracle 資料庫程式的軟體。它的選單、按鈕、訊息會顯示成什麼文字，都寫在 `Languages` 資料夾裡的**語言檔**（副檔名 `.lang`）。例如 `Taiwan.lang` 就是繁體中文版的介面文字。

問題是：

- 🔒 **語言檔被加密了**：用記事本打開只會看到一堆亂碼，沒辦法直接改。
- 🔍 **很難比對**：想知道「英文原文是什麼」、「簡體版怎麼翻」，沒有工具可以並排看。
- ⚠️ **很容易改壞**：語言檔有固定格式，少一行或多一行，PL/SQL Developer 的整個介面翻譯就會亂掉。

PLLangStudio 幫你解決這三件事：

| 它幫你做的事 | 就像是… |
|---|---|
| 自動**解密**語言檔，讓你看得懂 | 把上鎖的日記本打開 |
| 把兩種語言**並排比對**，連英文原文一起顯示 | 考卷旁邊放著標準答案 |
| 只讓你改「翻譯」，格式**不會被改壞** | 只能在空格裡填答案，題目不能塗改 |
| 改完再**加密**放回去 | 把日記本重新鎖好放回抽屜 |

## 2. 先認識幾個名詞

看懂這幾個詞，後面的說明就很好懂了。

| 名詞 | 意思 | 舉例 |
|---|---|---|
| **語言檔** | PL/SQL Developer 的介面翻譯檔，一種語言一個檔案 | `Taiwan.lang`、`Chinese.lang` |
| **筆** | 語言檔裡「一個介面元件」的翻譯資料 | 「取消」按鈕是一筆 |
| **字串** | 一筆裡面一段要翻譯的文字。一筆可以有好幾個字串，例如按鈕的「標題」和滑鼠移上去時的「提示」 | 標題「&取消」、提示「關閉視窗」 |
| **識別碼** | 每一筆的「身分證字號」，由視窗名稱和元件名稱組成。靠它才能在不同語言檔之間找到同一筆 | `AAMacrosEditDlg.ButtonPanel.CancelBtn.Button` |
| **英文原文** | 每一筆都附有英文，所有語言檔的英文都一樣，是翻譯的來源 | `&Cancel` |
| **主語系** | 拿來**參考**的語言檔，只能看不能改（🔒唯讀），預設是簡體中文 `Chinese.lang` | 像「參考答案」 |
| **副語系** | 你要**修改**的語言檔，預設是繁體中文 `Taiwan.lang` | 像「你的作業」 |
| **工作區** | 放你修改中檔案的資料夾。所有修改都先在這裡進行，不會直接動到 PL/SQL Developer | 像「草稿本」 |
| **部署** | 把工作區改好的語言檔，放回 PL/SQL Developer 讓它生效 | 像「把作業交出去」 |
| **用語對照表** | 一份「哪個詞要換成哪個詞」的清單，可以重複使用 | 「配置」→「設定」 |
| **例外詞** | 用語對照表裡刻意「不要換」的詞 | 「新建→新增」但「重新建立」不要變成「重新增立」 |

## 3. 第一次使用

### 步驟 1：打開程式

雙擊 **`PLLangStudio.exe`**，不需要安裝。

### 步驟 2：程式會自動幫你準備好

第一次打開時，程式會自動做這些事：

1. 在 exe 旁邊建立一個 **`workspace`**（工作區）資料夾。
   如果那裡沒辦法寫入（例如 exe 放在 `C:\Program Files`），會改建在 `文件\PLLangStudio\workspace`。
2. 自動找到 PL/SQL Developer 的語言資料夾，預設位置是：
   `C:\Program Files\PLSQL Developer 17\Languages`
   找不到時會請你自己選（**檔案 ▸ PL/SQL 語言目錄…**）。
3. 自動把 `Chinese.lang`（簡體）和 `Taiwan.lang`（繁體）**複製一份**到工作區。
4. 打開比對畫面：主語系＝簡體，副語系＝繁體。

> 💡 **放心**：程式複製的是「副本」，PL/SQL Developer 裡的原檔完全不會被動到，直到你按「部署」為止。

```
├─ 工作區：…  切換工作區  💾加密存檔  🚀部署  📝記事本  復原 重做 … ← ② 工具列

│  Taiwan  副語系├────┬────┬────────┬────┬──────┬──────┬──────
│              │ #  │狀態│ 識別碼  │欄位│ 英文  │主語系 │副語系  ← ⑥
│ ③ 檔案清單    │ 1  │    │ …Cancel │標題│&Cancel│&取消  │&取消

│  …           │
├──────────────┴─────────────────────────────────────────────
│ ✎ 0 個字串未存檔 ｜ 錯誤 0／警告 261 ｜ 第 1 / 6672 列 ｜ 已部署  ← ⑧ 狀態列
└────────────────────────────────────────────────────────────
```

| 編號 | 名稱 | 用途 |
|---|---|---|
| ① | **選單列** | 所有功能都在這裡：**檔案**（存檔、部署、切換工作區）、**編輯**（復原、尋找、批次工具、主題、字型）、**關於**（使用說明） |
| ② | **工具列** | 最常用的按鈕，按一下就能用 |
| ③ | **檔案清單** | **上方**是「工作區」裡的語言檔，旁邊標著哪個是主語系（🔒 唯讀）、哪個是副語系；**下方**是 PL/SQL Developer 裡所有的語言檔。中間的分隔線可以上下拖曳 |
| ④ | **主語系／副語系選擇** | 用下拉選單換成任何一種語言，例如把副語系換成日文。主語系和副語系不能是同一個檔案，另一邊已選的檔案會變成灰色不能選 |
| ⑤ | **篩選和搜尋** | 只看某一種狀態的列，或用關鍵字搜尋 |
| ⑥ | **對照表格** | 一列就是一個字串，主語系和副語系永遠在同一列，捲動時不會錯位 |
| ⑦ | **詳細區** | 顯示選到那一列的完整資訊，並可以編輯多行文字 |
| ⑧ | **狀態列** | 告訴你還有幾個字串沒存檔、有幾個錯誤或警告、目前在第幾列 |

### 在檔案清單上按右鍵

| 選項 | 作用 |
|---|---|
| 設為主語系 | 把這個語言檔當成參考 |
| 設為副語系 | 把這個語言檔當成要修改的對象 |
| 匯入工作區 | （下方清單）把 PL/SQL Developer 的語言檔複製到工作區。直接**雙擊**也可以 |
| 用記事本開 .txt | （上方清單）用記事本打開解密後的文字檔 |
| 從工作區移除… | （上方清單）把用不到的語言檔從工作區拿掉。會先備份到 `backup\`，**PL/SQL Developer 裡的檔案不受影響**，之後要用再匯入一次就好。目前的主語系、副語系不能移除，要先切換到別的檔案 |
| 開啟所在資料夾 | 在檔案總管裡找到這個檔案 |

> 💡 在上方「工作區」清單**雙擊**檔案，就會把它設為副語系。

## 5. 一步一步：修改一個翻譯

假設你想把「取消」按鈕的文字改成「放棄」：

1. **找到那一列**：在搜尋框輸入 `取消`，搜尋範圍選「副語系」，表格就只剩下有「取消」的列。
2. **開始編輯**：在那一列的「副語系」格子上**雙擊**，或選好那一列後按 **F2**。
3. **輸入新文字**：輸入 `&放棄`，按 **Enter**。
   - `&` 不要刪掉！它是**快速鍵記號**：`&` 後面的那個字，在選單或按鈕上會加底線，按住 Alt 再按那個鍵就能直接觸發。
   - 中文翻譯常把快速鍵寫在括號裡，例如英文 `&Save As` 翻成 `另存為(&A)`，這樣按 Alt+A 就能觸發。
   - 英文有 `&`、翻譯卻沒有時，程式會顯示「警告」提醒你。
   - 按 Enter 之後，游標會自動跳到下一列，方便你連續修改。
4. **確認修改**：那一列的狀態會出現藍色的 **✎**，代表「已修改、還沒存檔」。狀態列也會顯示「✎ 1 個字串未存檔」。
5. **改錯了？** 按 **Ctrl+Z** 復原，按 **Ctrl+Y** 重做。
6. **存檔**：按 **Ctrl+S**。這時只存進工作區，PL/SQL Developer 還看不到。
7. **部署**：**檔案 ▸ 部署到 PL/SQL Developer…**，詳細說明見[第 8 節](#8-存檔和部署讓修改生效)。

### 多行的字串怎麼改？

有些說明文字很長、有好幾行，表格格子沒辦法直接改（欄位會顯示「標題（多行）」）。這時：

1. 點選那一列。
2. 在下方**詳細區**的編輯框裡修改，可以按 Enter 換行。
3. 按「**套用**」。想放棄修改就按「**還原**」。

### 詳細區會告訴你什麼？

- **元件路徑**：這段文字在哪個視窗、哪個元件上。
- **說明**：PL/SQL Developer 寫給翻譯者看的提示，幫助你理解原意。
- **差異標色**：把主語系和副語系一個字一個字比對（就像「找不同」）：
  - 🟥 紅底：主語系有、但副語系不一樣的字
  - 🟩 綠底：副語系改過或多出來的字
  - 🔴 深紅底白字：**殘留的簡體字**，應該要改成繁體

## 6. 表格裡的小符號是什麼意思？

「狀態」欄會出現這些符號，副語系的格子也會塗上對應的底色：

| 符號 | 名稱 | 意思 | 要不要處理？ |
|---|---|---|---|
| `≠` | 不同 | 主語系和副語系的文字不一樣 | 通常正常（簡體和繁體本來就不同） |
| `✎` | 已修改 | 你改過，**還沒存檔** | 記得按 Ctrl+S |
| `簡` | 殘留簡體 | 副語系裡還有簡體字，例如「后」應該是「後」 | ✅ 建議修正 |
| `⚠` | 疑似漏翻 | 副語系跟英文一模一樣，可能忘了翻譯，例如 `Tablespace` | 看情況，專有名詞可以不翻 |
| `◐` | 單邊 | 只有其中一邊有這一筆，常見於比對不同版本的語言檔 | 通常不用處理 |
| `✖` | 錯誤 | 這個修改會讓程式出問題，**有錯誤時不能存檔** | ❗ 一定要修正 |
| `!` | 警告 | 可能有小問題，但可以存檔 | 看情況 |

把滑鼠移到「狀態」格子上，會顯示詳細原因。

### 什麼情況會是「錯誤」？

- **佔位符不見了或多出來**：英文裡的 `%1`、`%2`…是程式之後要填入數字或名字的位置。
  例如 `%1 records deleted` 會顯示成「5 records deleted」。
  如果翻譯寫成「條記錄已刪除」（少了 `%1`），程式就不知道數字要放哪裡，所以**不能存檔**。

### 什麼情況會是「警告」？

- 英文有快速鍵 `&`，翻譯卻沒有
- 翻譯跟英文完全一樣（疑似漏翻）
- 有殘留的簡體字
- 開頭或結尾的空白跟英文不一樣

### 篩選按鈕

表格上方的按鈕（`全部 6,672`、`不同 5,491`…）會顯示每種狀態有幾列。按一下就**只顯示那一種**，例如按「殘留簡體」就能一次找出所有還沒改的簡體字。

搜尋框旁邊的下拉選單可以選搜尋範圍：**全部／英文／主語系／副語系／識別碼**。

用 **F3**／**Shift+F3** 可以跳到下一個／上一個「不同」的列。

## 7. 一次改很多：批次工具

一個一個改太慢？在「**編輯**」選單裡有三種批次工具。它們都有同樣的保護：

> ✅ **先預覽，再套用**：會先列出「哪些字串會被改、改之前、改之後」，每一列都可以取消勾選，確定後按「套用」才會真的修改。
> ✅ **整批一次復原**：套用後如果後悔，按一次 Ctrl+Z 就能全部還原。
> ✅ **只改副語系的翻譯**，英文、識別碼和格式都不會被動到。

### 🔍 尋找取代（Ctrl+H）

在副語系裡把某個詞全部換掉，例如把「宏」全部換成「巨集」。

- **規則運算式**：進階用法。例如尋找 `%(\d)`、取代成 `{\1}`。不懂的話不用勾。
- **區分大小寫**：勾選後，`Table` 和 `table` 會被當成不同的字。

### 簡→繁（主語系 → 副語系）

把主語系的簡體中文，用 OpenCC 轉換成**台灣繁體和台灣用語**，例如「文件→檔案」、「数据库→資料庫」，再填進副語系。

- 只想轉換幾列：先用滑鼠選好多列（按住 Ctrl 或 Shift 點選），再執行。
- 沒有選取或只選一列時，會轉換全部。

### 📖 用語對照表

把常用的替換規則存起來，以後可以重複使用。程式內建了一批整理好的台灣用語規則：

| 原本 | 改成 | 原本 | 改成 |
|---|---|---|---|
| 宏 | 巨集 | 會話 | 工作階段 |
| 配置 | 設定 | 事務 | 交易 |
| 訪問 | 存取 | 首選項 | 偏好設定 |
| 文本 | 文字 | 常規 | 一般 |
| 列表 | 清單 | 模板 | 範本 |
| 通過 | 透過 | 獲取 | 取得 |
| 天后 | 天後 | …… | 共 40 條 |

在用語對照表視窗裡可以：

- **新增／刪除**規則，**勾選或取消**「啟用」
- 設定**例外詞**：用逗號 `,` 分隔多個詞。例如「通過→透過」的例外是「通過計數」，因為那是測試的 Pass count，意思是「測試通過」，不能改成「透過」。
- **上移／下移**：規則**由上往下**依序套用，**較長的詞要放上面**。例如「配置文件→設定檔」要排在「配置→設定」前面，不然「配置文件」會先被改成「設定文件」。
- **殘留簡體字的例外詞**：有些字在繁體也是對的（例如「游標」的游、「批准」的准），放在這裡就不會被誤判成簡體字。
- 按「**儲存並套用到副語系…**」，就會預覽並套用全部規則。

## 8. 存檔和部署：讓修改生效

修改要經過「**存檔**」和「**部署**」兩個步驟，才會出現在 PL/SQL Developer 裡。

```
 你修改             存檔 Ctrl+S              部署
 ───────►  [工作區裡的語言檔]  ──────────►  [PL/SQL Developer 的語言檔]
 （表格）     草稿本，隨時可以改      交作業，重新啟動 PL/SQL Developer 後生效
```

### 💾 加密存檔（Ctrl+S）

- 只會存進**工作區**，不會影響 PL/SQL Developer。
- 存檔前會自動檢查：
  - 有「**錯誤**」→ 不能存檔，會列出問題並跳到那一列。
  - 有「**警告**」→ 會問你要不要繼續存檔。
- 存檔前會先把舊檔**備份**到 `workspace\backup\`。

### 🚀 部署到 PL/SQL Developer

1. 選 **檔案 ▸ 部署到 PL/SQL Developer…**。還有沒存檔的修改時，會先問你要不要存檔。
2. 程式會告訴你這次跟 PL/SQL Developer 裡的版本**有幾筆不同**，請你確認。
3. PL/SQL Developer 裝在 `C:\Program Files`，Windows 會跳出 **UAC 視窗**（「是否允許此應用程式變更您的裝置？」），請按「**是**」。
   - 按「否」也沒關係，修改還保留在工作區，下次再部署就好。
4. 程式會先備份 PL/SQL Developer 裡的舊檔，寫入後再**讀回來逐一比對**，確定一個位元組都沒寫錯。
5. **重新啟動 PL/SQL Developer**，就能看到新的翻譯了。

> 💡 檔案清單上方的「已部署」欄會顯示 ✓ 或「未部署」，狀態列也會提醒你有沒有尚未部署的修改。

## 9. 用記事本修改

喜歡用記事本一次看整份檔案？也可以：

1. 選 **檔案 ▸ 用記事本開啟副語系**。程式會打開工作區裡解密好的 `.txt` 檔。
2. 在記事本裡修改翻譯，然後存檔。
3. 回到 PLLangStudio，**大約 1 秒內就會自動載入**，改過的地方會標成 ✎。
4. 記得在 PLLangStudio 按 Ctrl+S 存檔。

### ⚠️ 記事本修改的規則

`.txt` 裡每一筆長這樣，**只能改最後幾行的中文翻譯**：

```
||010101010001000001000000000000     ← 旗標（不要動）
AAMacrosEditDlg                      ← 視窗名稱（不要動）
ButtonPanel                          ← 元件路徑（不要動）
CancelBtn
Button
&Cancel                              ← 英文原文（不要動）
&取消                                 ← ✏️ 只能改這種翻譯行
```

- **不要新增或刪除行**，也不要改檔頭（最上面 `:` 開頭的幾行）。
- 存檔時請用 **UTF-8** 編碼（Windows 11 記事本預設就是）。

### 如果表格和記事本都有修改？

程式會問你要用哪一邊：

- **是** → 改用記事本的內容（表格裡的修改會被捨棄）
- **否** → 保留表格的修改（記事本的修改會被覆蓋）

### 如果記事本的檔案壞掉了？

例如不小心存成亂碼、刪掉了整筆資料，或改了檔頭，程式**不會載入**它，而是：

1. 先把那個 `.txt` 備份到 `workspace\backup\`（你的內容不會不見）。
2. 改用工作區語言檔原本的內容。
3. 跳出訊息告訴你哪裡有問題、備份放在哪裡。

## 11. 安全機制：不怕改壞

PLLangStudio 處理的是 PL/SQL Developer 正在使用的檔案，所以設計了很多層保護：

| 保護 | 說明 |
|---|---|
| 🛡️ **原檔不會被直接修改** | 所有修改都在工作區進行，按「部署」才會寫回 PL/SQL Developer |
| 💾 **每次都會備份** | 存檔、部署、匯入覆蓋之前，都會把舊檔複製到 `workspace\backup\`，檔名加上日期時間 |
| ✍️ **不會寫到一半** | 先寫到暫存檔，完成後才一次換成正式檔名。就算中途停電，檔案也不是舊的就是新的，不會壞一半 |
| 🔍 **部署後會驗證** | 寫進 PL/SQL Developer 後，會讀回來逐位元組比對 |
| 🧱 **格式受保護** | 只能改翻譯，旗標、英文、識別碼都改不到；記事本的 `.txt` 格式不對也不會被接受 |
| ❗ **錯誤會擋下來** | 佔位符 `%1` 不見之類會讓程式出問題的修改，無法存檔 |
| 🔔 **離開前會提醒** | 還有沒存檔的修改時，關閉程式或切換主語系、副語系前都會先問你 |
| 🩹 **設定檔壞了也能開** | 設定檔損毀時，會改名成 `.corrupt` 保留下來，再用預設值開啟 |

### 怎麼從備份救回來？

1. **先關閉 PLLangStudio**。
2. 打開 `workspace\backup\` 資料夾。
3. 找到想要的版本。檔名格式是 `名稱_年月日_時分秒_微秒.lang`，例如 `Taiwan_20261026_193557_123456.lang`。
   - 檔名開頭是 `installed_` 的，是**部署前**從 PL/SQL Developer 備份出來的檔案。
4. 把它複製到 `workspace\lang\`，改名成原本的名稱（例如 `Taiwan.lang`），取代舊檔。
5. **刪掉 `workspace\txt\` 裡同名的 `.txt`**（例如 `Taiwan.txt`）。
   這一步很重要：不刪的話，程式會以為舊的 `.txt` 是你用記事本做的修改，又把它載入回來。刪掉後程式會自動重新產生。
6. 重新打開 PLLangStudio。

## 13. 常見問題

**Q：我改了翻譯，PL/SQL Developer 怎麼還是舊的？**
A：要做完三件事：① 在 PLLangStudio 按 **Ctrl+S** 存檔 → ② **檔案 ▸ 部署到 PL/SQL Developer** → ③ **重新啟動 PL/SQL Developer**。

**Q：為什麼主語系的格子不能改？**
A：主語系是「參考答案」，設計成唯讀（🔒），避免不小心改到比對的基準。想改某個語言檔，就把它設為副語系。

**Q：有些列的格子雙擊沒反應？**
A：那是多行的字串，「欄位」欄會寫「（多行）」。請在下方詳細區編輯，再按「套用」。

**Q：按 Ctrl+S 說「有錯誤，不能存檔」？**
A：通常是佔位符 `%1`、`%2` 不見了。按「錯誤」篩選按鈕找出那幾列，把佔位符補回去。

**Q：「疑似漏翻」很多，都要翻嗎？**
A：不一定。像 `Tablespace`、`Foreign key` 這類資料庫專有名詞，有些人習慣保留英文。看你的需求決定。

**Q：「游標」被標成簡體字？**
A：不會。程式內建「游標」和「批准」為例外詞。如果發現其他被誤判的詞，可以在 **用語對照表** 下方的「殘留簡體字的例外詞」加進去。

**Q：部署時 UAC 視窗按了「否」怎麼辦？**
A：沒關係，修改還在工作區，再部署一次並按「是」就好。

**Q：可以比對其他語言嗎？**
A：可以。主語系、副語系都能換成任何語言檔，例如主語系選日文、副語系選繁體。下方清單裡的語言檔雙擊就能匯入工作區。

**Q：舊版的語言檔（例如 Hungarian.lang）有些列標著 ◐？**
A：那個檔案是比較舊的版本，有些筆只存在其中一邊，程式會標成「單邊」讓你知道。這是正常的。

**Q：換新版的 exe 時要注意什麼？**
A：只要換掉 `PLLangStudio.exe` 就好，**不要刪掉旁邊的 `workspace` 資料夾**，裡面是你所有的修改和備份。

## 14. 檔案放在哪裡？

```
PLLangStudio.exe
workspace\                ← 工作區（你的所有修改都在這裡）
├─ lang\                  ← 匯入的語言檔（加密），存檔就是寫到這裡
├─ txt\                   ← 解密後的文字檔，給記事本用
├─ backup\                ← 所有備份，檔名有日期時間
├─ glossary.json          ← 用語對照表
└─ settings.json          ← PL/SQL 語言目錄、上次的主語系與副語系
```

| 檔案 | 位置 | 內容 |
|---|---|---|
| 程式設定 | `%APPDATA%\PLLangStudio\app.json` | 上次使用的工作區、主題、字型與大小 |
| PL/SQL Developer 語言檔 | `C:\Program Files\PLSQL Developer 17\Languages\` | 部署的目的地 |

想換到別的工作區（例如放到隨身碟），用 **檔案 ▸ 切換工作區…**。

## 15. 從原始碼執行（uv run）

一般使用者直接雙擊 `PLLangStudio.exe` 就好，**不需要看這一節**。

這一節是給「想直接跑程式碼、修改程式、或自己打包 exe」的人看的。

### uv 是什麼？

[uv](https://docs.astral.sh/uv/) 是 Python 的「管家」，它會幫你：

- 📦 **準備 Python**：專案需要 Python 3.14，電腦上沒有的話，uv 會自動下載，不會影響電腦上其他的 Python。
- 🧰 **準備套件**：PySide6（畫面）、OpenCC（簡轉繁）、pytest（測試）……照 `uv.lock` 裡記錄的版本一個不差地裝好。
- ▶️ **用對的環境執行**：`uv run 指令` 的意思是「在這個專案專用的環境裡執行這個指令」。

> 💡 打個比方：`uv run` 就像「進到專案的專屬教室再上課」，教室裡的課本（套件）都已經照課表準備好了。

### 步驟 1：安裝 uv（只要做一次）

打開 **PowerShell**，輸入下面任一個指令：

```powershell
winget install --id=astral-sh.uv -e
```

或

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

裝好後**關掉 PowerShell 再重開**，輸入下面這行確認有裝好：

```powershell
uv --version
```

看到 `uv 0.11.18` 之類的版本號就成功了。

### 步驟 2：進到專案資料夾

> ⚠️ **最重要的一步**：所有 `uv run` 指令都必須在**專案資料夾**裡執行，也就是有 `pyproject.toml` 的那個資料夾。

```powershell
cd C:\Users\game\langwork\LangEditor
```

在別的資料夾執行，會看到這個錯誤：

```
ModuleNotFoundError: No module named 'pllangstudio'
```

看到它就代表「不在專案資料夾裡」，先 `cd` 進去再試一次。

### 步驟 3：準備環境（第一次，或套件有更新時）

```powershell
uv sync
```

uv 會建立 `.venv\` 資料夾，並安裝所有套件（包含測試與打包工具）。第一次大約需要一兩分鐘，之後只會檢查，一下子就好。

> 💡 不做這一步也可以：第一次執行 `uv run` 時，uv 會自動幫你準備好。

### 步驟 4：執行指令

| 想做什麼 | 指令 | 說明 |
|---|---|---|
| **打開程式** | `uv run python -m pllangstudio` | 跟雙擊 exe 一樣會打開視窗。`-m pllangstudio` 的意思是「執行 pllangstudio 這個套件」 |
| **執行全部測試** | `uv run pytest` | 跑所有自動測試，最後看到 `142 passed` 之類的訊息就代表全部通過 |
| 測試時顯示更多資訊 | `uv run pytest -v` | 每個測試一行，看得到名稱與結果 |
| 只跑某個資料夾的測試 | `uv run pytest tests/core` | 只測核心邏輯（比較快，不需要畫面） |
| 只跑名稱含某個字的測試 | `uv run pytest -k glossary` | 只跑名稱裡有 `glossary` 的測試 |
| 把警告也當成錯誤 | `uv run pytest -W error` | 正式發佈前建議用這個，確保測試輸出乾淨 |
| **打包成 exe** | 見下方 | 產生 `dist\PLLangStudio.exe` |
| 查看 Python 版本 | `uv run python --version` | 應該顯示 `Python 3.14.x` |
| 查看程式版本 | `uv run python -c "import pllangstudio; print(pllangstudio.__version__)"` | 例如 `0.2.0` |

### 打包成 exe

```powershell
uv run pyinstaller --noconfirm --onefile --windowed --collect-all opencc --name PLLangStudio --specpath build pllangstudio/__main__.py
```

每個參數的意思：

| 參數 | 意思 |
|---|---|
| `--noconfirm` | 覆蓋舊的打包結果時不要再問 |
| `--onefile` | 打包成**單一個** exe，方便複製 |
| `--windowed` | 執行時不要跳出黑色的命令列視窗 |
| `--collect-all opencc` | 把 OpenCC 的字典檔一起包進去。⚠️ **不能省略**，否則 exe 裡的簡轉繁會找不到字典 |
| `--name PLLangStudio` | exe 的名稱 |
| `--specpath build` | 把自動產生的 `PLLangStudio.spec` 放在 `build\` 底下，不弄亂專案根目錄 |
| `pllangstudio/__main__.py` | 程式的進入點 |

完成後：

- 成品在 **`dist\PLLangStudio.exe`**，約 52 MB，大約需要一分鐘。
- 打包過程的暫存檔和 `PLLangStudio.spec` 都在 `build\`，可以刪掉，下次打包會重新產生。

> ⚠️ 打包前請先**關閉正在執行的 PLLangStudio.exe**，否則舊的 exe 被占用，沒辦法覆蓋。

### ⚠️ 從原始碼執行時要注意：工作區會跟 exe 共用設定

用 `uv run python -m pllangstudio` 打開程式時：

1. 工作區預設會建在**目前所在的資料夾**，也就是專案資料夾裡的 `workspace\`（git 不會追蹤它）。
2. 程式會把它記成「**上次使用的工作區**」，存在 `%APPDATA%\PLLangStudio\app.json`。
3. 之後雙擊 exe，exe 也會打開**這個**工作區，而不是 exe 旁邊原本的那個。

想換回原本的工作區，在 exe 裡選 **檔案 ▸ 切換工作區…**，選回 `dist\workspace` 之類的資料夾就好，資料不會不見。

如果想讓開發用的程式**完全不影響** exe 的設定，可以暫時換一個設定資料夾來執行：

```powershell
$env:APPDATA = "$PWD\dev-appdata"; uv run python -m pllangstudio
```

這樣設定會存在專案裡的 `dev-appdata\`，不會動到平常的設定。這個做法只對目前這個 PowerShell 視窗有效，關掉就恢復。

### 常見問題

| 狀況 | 原因與解法 |
|---|---|
| `uv : 無法辨識 'uv' 詞彙` | uv 還沒裝好，或裝完沒有重開 PowerShell |
| `No module named 'pllangstudio'` | 不在專案資料夾裡，先 `cd` 到有 `pyproject.toml` 的資料夾 |
| 大部分測試被跳過（`skipped`） | 找不到 `C:\Program Files\PLSQL Developer 17\Languages`。大部分測試要讀取真實的語言檔，沒有安裝 PL/SQL Developer 時就會跳過，只剩不需要語言檔的少數測試會執行 |
| 打包時 `PermissionError` | `dist\PLLangStudio.exe` 還在執行中，先關掉它 |
| exe 的簡轉繁沒反應或閃退 | 打包時少了 `--collect-all opencc` |
