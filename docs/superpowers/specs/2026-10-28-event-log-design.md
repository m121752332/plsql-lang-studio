# 事件紀錄與事件檢視器 設計

日期：2026-10-28　狀態：已實作

## 目的

用 Loguru＋SQLite 記錄使用者的操作過程與錯誤。程式突然出錯時，可以從紀錄追查錯誤發生前做了什麼；日後有回報管道（ticket）時，使用者提供**事件編號**並附上匯出的紀錄。

## 範圍

- 記錄操作層級的事件與所有錯誤（含未預期的例外）。
- 依等級設定保留天數，過期自動清除。
- 「配置」視窗：外觀頁（主題、字型，從編輯選單搬來）與紀錄事件頁（保留天數）。
- 事件檢視器：篩選、檢視詳細內容、複製、匯出 zip。

不在範圍：記錄每一格翻譯的修改內容、上傳紀錄到遠端、ticket 系統本身。

## 做法

採用 **Loguru＋自訂 SQLite sink**。Loguru 負責記錄 API 與例外堆疊的格式化；sink 函式把每筆紀錄寫入 SQLite，查詢、篩選、清除直接用 SQL。

不採用：
- Loguru 寫文字檔再匯入 SQLite：多一層同步，沒有好處。
- 標準 `logging`：使用者指定 Loguru，且 Loguru 的例外堆疊較利於追查。

## 資料層：`pllangstudio/eventlog.py`

不依賴 Qt（比照 `appconfig.py` 放在套件根目錄）。

| 函式 | 說明 |
|---|---|
| `setup(db_path)` | 啟動時呼叫：建立資料表、掛上 sink、依保留天數清除過期紀錄 |
| `query(groups, since, keyword, limit)` | 回傳符合條件的紀錄，新的在前；`groups` 是等級群組（資訊／警告／錯誤）；`keyword` 為 `#數字` 時依事件編號查詢 |
| `purge(retention)` | 依各等級群組的保留天數刪除過期紀錄，回傳刪除筆數 |
| `stats()` | 回傳總筆數與資料庫大小 |
| `export_zip(records, dest)` | 匯出 zip（內容見「事件檢視器」） |

- 資料庫位置：`%APPDATA%\PLLangStudio\events.db`（與 `app.json` 同層）。
- 測試一律傳入 `tmp_path` 底下的路徑，不碰真實位置。

### 資料表 `events`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | **事件編號** |
| `time` | TEXT | ISO 8601 UTC 時間（毫秒），顯示時轉本地時間 |
| `level` | TEXT | Loguru 等級名稱 |
| `category` | TEXT | 類別，例如 工作區、匯入、存檔、部署 |
| `message` | TEXT | 訊息 |
| `detail` | TEXT | 例外堆疊等詳細內容，可為空 |
| `app_version` | TEXT | 程式版本 |

`time` 與 `level` 建索引。使用 WAL 模式，避免檢視器讀取時擋住寫入。

### 等級與保留天數

| 群組 | Loguru 等級 | 預設天數 | app.json 欄位 |
|---|---|---|---|
| 資訊 | DEBUG、INFO、SUCCESS | 90 | `log_days_info` |
| 警告 | WARNING | 90 | `log_days_warning` |
| 錯誤 | ERROR、CRITICAL（嚴重錯誤） | 30 | `log_days_error` |

- 天數範圍 1～3650；超出範圍或格式錯誤時用預設值。
- 讀寫由 `appconfig.py` 新增的 `log_retention()`／`remember_log_retention()` 負責。
- 清除時機：每次啟動、配置頁按「確定／套用」後、按「立即清除過期紀錄」。

### 記錄點（操作層級）

每項記錄結果：成功（INFO／SUCCESS，附筆數等摘要）或失敗（ERROR，附錯誤訊息）。

- 程式啟動／結束（版本、作業系統）
- 開啟、切換工作區
- 匯入語言檔、從工作區移除
- 切換主語系／副語系
- 存檔、部署（含提權）
- 批次修改
- 用語對照表變更
- 從記事本重新載入
- 配置變更

不記錄單筆字串的翻譯內容。

### 錯誤處理

- **未預期的例外**：掛 `sys.excepthook`，記為 CRITICAL（含完整堆疊），顯示對話框「發生未預期的錯誤（事件編號 #1234）。回報問題時請提供此編號，並從事件檢視器匯出紀錄。」
- **既有錯誤對話框**（存檔失敗、部署失敗、.txt 格式錯誤……）：同時記為 ERROR，訊息末尾加上事件編號。
- **紀錄本身失敗**：寫入失敗不可影響主程式（吞掉例外）。資料庫損毀時比照 `app.json` 改名為 `.corrupt` 後重建。

## 介面

### 選單

- 新增「配置(&S)」選單，位於「編輯」與「關於」之間，內含「配置…」與「事件檢視器…」。
- 移除編輯選單的「主題」「字型」子選單。

### 配置視窗：`ui/settings_dialog.py`

左側頁籤清單、右側內容，下方「確定／取消／套用」。

- **外觀**：主題（亮色／暗色／跟隨系統）、字型、字體大小。沿用 `ThemeManager`、`FontManager`，`font_dialog.py` 的內容併入此頁。
- **紀錄事件**：資訊／警告／錯誤三個保留天數欄位、目前筆數與大小、「開啟事件檢視器」「立即清除過期紀錄」按鈕。

### 事件檢視器：`ui/event_viewer.py`

非強制回應的獨立視窗，可邊操作主程式邊查看。

- 篩選列：等級（資訊／警告／錯誤勾選）、期間（今天／最近 7 天／最近 30 天／全部）、搜尋（`#1234` 依事件編號定位）、重新整理。
- 表格欄位：編號、時間、等級、類別、訊息；依等級上色，顏色放在 `theme.py` 的 `Colors`（亮色、暗色各一組）。
- 下方詳細內容：選取列的完整訊息與例外堆疊。
- 按鈕：「複製選取」、「匯出篩選結果…」。
- 匯出檔名 `PLLangStudio-events-YYYYMMDD-HHMMSS.zip`，內含：
  - `events.txt`：可讀文字，每筆一段（編號、時間、等級、類別、訊息、詳細內容）。
  - `system.txt`：程式版本、Python 版本、Qt 版本、Windows 版本。
  - 不含語言檔內容。

## 測試

- `tests/test_eventlog.py`：寫入後可查詢、等級／期間／關鍵字／事件編號篩選、依等級群組清除、天數設定容錯、資料庫損毀時改名重建、匯出 zip 內容。
- `tests/ui/`（pytest-qt）：配置視窗存取保留天數與外觀設定、事件檢視器篩選與詳細內容、未預期例外會記錄並顯示事件編號、既有錯誤對話框附事件編號。
- 測試可平行執行：每個測試用自己的 `tmp_path` 資料庫，結束時移除 Loguru sink。
