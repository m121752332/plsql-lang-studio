# 用 Loguru＋SQLite 記錄操作與錯誤，事件編號用來回報問題

程式突然出錯時，原本只有對話框，關掉就沒了，無法追查使用者之前做了什麼。我們加入**事件紀錄**：記錄每個操作的結果與所有錯誤，存在 `%APPDATA%\PLLangStudio\events.db`（SQLite）。每筆有**事件編號**，錯誤對話框會顯示它；回報問題時提供編號，並從**事件檢視器**匯出 zip。

做法：

- `pllangstudio/eventlog.py`（不依賴 Qt）掛一個 Loguru sink，同步寫入 SQLite（WAL 模式），寫入後即可取得事件編號。
- 記錄操作層級：開啟／切換工作區、匯入、移除、切換主語系／副語系、存檔、部署、批次修改、用語對照表、記事本重新載入、配置變更、程式啟動與結束。**不記錄字串的翻譯內容**，匯出的 zip 也不含語言檔。
- 等級分三群保留：資訊（DEBUG／INFO／SUCCESS）90 天、警告 90 天、錯誤（ERROR／CRITICAL）30 天，可在「配置 ▸ 紀錄事件」調整（1～3650 天），存在 app.json。啟動時與套用配置後清除過期紀錄。
- 時間存 UTC，顯示時轉本地時間。
- 未預期的例外由 `sys.excepthook` 攔截，記為嚴重錯誤並顯示事件編號。
- 紀錄本身失敗（資料庫損毀、被鎖、沒有權限）不可影響主程式；損毀的資料庫改名為 `.corrupt` 後重建（比照 app.json）。

## Considered Options

- **標準 `logging`**：不需要額外套件，但 Loguru 的 API 較簡潔、例外堆疊較完整。採用 Loguru。
- **只寫文字檔**：查詢、依等級清除、取得事件編號都不方便。不採用。
- **記錄每個字串的修改內容**：追查最完整，但紀錄量大，且翻譯內容會出現在使用者回報的紀錄裡。不採用；需要時可從 backup 資料夾比對。
