# 操作成功與一般資訊用提示訊息，錯誤與詢問用對話框

原本所有通知都是對話框（存檔成功則是狀態列的一行字）。存檔、部署、從記事本重新載入這類常做的操作，每次都要按「確定」很打斷工作；狀態列的字又太小，容易沒注意到。我們參考 UniGetUI，加入**提示訊息**：在主視窗右下角滑入的圓角卡片，幾秒後自動淡出。

分級原則：

- **提示訊息**：操作成功（存檔、部署）、一般資訊（已從記事本重新載入、沒有需要修改的字串）、不需要使用者處理的提醒（主語系和副語系不能選同一個檔案）。
- **對話框**：錯誤（存檔失敗、部署失敗、.txt 格式錯誤……）與所有「要不要……？」的詢問。錯誤必須讓使用者看到並確認，不能幾秒後自己消失。
- 「找不到 PL/SQL Developer」維持對話框，因為後面緊接著選資料夾的對話框，需要先說明原因。

做法：

- `ui/toast.py` 的 `ToastHost` 掛在主視窗上，負責在右下角（狀態列上方）由下往上堆疊，最多 3 則，超過時最舊的先收掉；視窗縮放時跟著移動。`Toast` 是單一則卡片，有圖示、標題、內文與 ✕，滑鼠停在上面時暫停倒數。
- 種類有成功（✓）、資訊（ℹ）、提醒（⚠），停留 4／4／6 秒。顏色放在 `theme.py` 的 `Colors`，亮色與暗色各一組（見 [ADR-0013](0013-theme-modes.md)）。
- `MainWindow` 跟 `ask`、`info` 一樣可以注入 `toast`，測試時換掉即可檢查顯示了什麼。

## Considered Options

- **Windows 系統通知**（通知中心）：程式縮小時也看得到，但需要額外套件或系統匣圖示，樣式由系統決定，也不容易用 pytest-qt 測試。不採用。
- **錯誤也改用提示訊息**：錯誤若自己消失，使用者可能根本不知道存檔失敗。不採用。
- **繼續用狀態列**：字太小、位置太邊緣，而且無法區分成功與提醒。不採用。
