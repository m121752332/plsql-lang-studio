# 測試以 Languages 目錄的真實語言檔為準，核心模組用 pytest、畫面用 pytest-qt 冒煙測試

`.lang` 格式是逆向分析出來的（見 [ADR-0001](0001-lang-file-format.md)），自己編的測試資料無法證明真實檔案也能正確處理。所以核心測試直接讀 PL/SQL Developer 的 Languages 目錄（唯讀；需要寫入時先複製到暫存資料夾），找不到該目錄時就略過這些測試。

**核心模組（pytest）**

- 全部 14 個語言檔：解密→解析→寫回，逐 byte 跟原檔相同。
- 解析後的筆數正確：13 個檔案 5,876 筆，Hungarian 5,695 筆。各語言的英文原文完全一致。
- 依識別碼對齊：Chinese 對 Taiwan 全部配對；Chinese 對 Hungarian 能正確標出單邊的筆。
- 修改一個字串：寫回後只有那一行改變。翻譯行數改變時，旗標 p9–p11 也同步更新，而且能再次正確解析。
- 用語對照表的例外：「新建」→「新增」不會改到「重新建立」。
- 檢查規則：佔位符缺漏要判為錯誤；「天后」要判為殘留簡體，「游標」不能誤判。
- 原子存檔：模擬寫入中途失敗，原檔不變。

**畫面（pytest-qt 冒煙測試）**

- 開啟 MASTER=Chinese、SLAVE=Taiwan，列數與篩選按鈕上的筆數正確。
- MASTER 的格子不能進入編輯；編輯 SLAVE 後狀態變成 `✎`，按 Ctrl+Z 能還原。
- 切換 SLAVE 時，選取停在同一個識別碼上。

**需要人工驗收的部分**：部署時的 UAC 流程，以及打包後的 exe 能否在乾淨的環境啟動。自動測試做不到，每次發佈前要手動確認一次。
