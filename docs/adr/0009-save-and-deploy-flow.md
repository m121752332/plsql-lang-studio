# 存檔與部署：先備份、原子寫入、寫完讀回驗證

語言檔一旦寫壞，PL/SQL Developer 的整個介面翻譯都會出錯，所以所有寫入都遵守同一套流程，不允許只寫一半。

**存檔（Ctrl+S，只寫工作區）**

1. 檢查格式：旗標與行數吻合，並執行 [ADR-0011](0011-validation-rules.md) 的檢查。有「錯誤」時不能存檔，有「警告」時列出來讓使用者確認。
2. 把舊檔備份到 `backup\<名稱>_<日期時間>.lang`。
3. 先寫到 `<名稱>.lang.tmp`，再用 `os.replace` 換成正式檔名，確保檔案不是舊的就是新的，不會只寫一半。
4. 同步重新產生 `txt\<名稱>.txt`。

**部署（寫回 PL/SQL Developer 的 Languages 目錄）**

1. 比較工作區與 Languages 目錄裡的同名檔，顯示有幾筆不同，請使用者確認。
2. 把 Languages 裡的舊檔備份到工作區的 `backup\`。
3. 先嘗試直接寫入。權限不足時才透過 UAC 用系統管理員身分複製，使用者在 UAC 按「否」時，修改仍保留在工作區。
4. 寫完後讀回目標檔，逐 byte 比對。不一致就報錯，並告訴使用者備份放在哪裡。
5. 提示使用者重新啟動 PL/SQL Developer 才會生效。

**匯入**：從 Languages 複製到工作區的 `lang\`，並解密到 `txt\`。工作區已經有同名檔而且內容不同時，先備份再詢問是否覆蓋。
